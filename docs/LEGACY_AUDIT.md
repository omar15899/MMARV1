# Audit of MMARV1 v1 (branch `main`, and its four siblings)

Date: 2026-07-27. Auditor: full read of all 1 825 lines across five modules, plus
execution of the library against its own reference script
(`Scripts/pruebaMMAR1.py`, Lockheed Martin daily close, 7 049 rows,
1995-03-17 → 2023-03-17).

Every claim below that carries a number was **observed by running the code**, not
inferred from reading it. The probe is preserved at `docs/probes/legacy_probe.py`.
Two hypotheses I formed while reading did **not** survive execution and are
recorded as such in §5 — they are fragilities, not defects.

---

## 0. Executive finding

> **The MMAR simulator does not simulate an MMAR.**
> The multifractal trading time is generated, and then discarded. The simulated
> price is a function of the fractional Brownian motion alone.

Observed:

```
max |price − Price[-1]·exp(x_t)|  =  0.000e+00      (exactly zero, all 8192 points)
kurtosis of simulated log-returns =  0.064          (Gaussian fBm ⇒ ≈ 0)
kurtosis of real LMT log-returns  =  8.8
```

`θ(t)` is computed, normalised, returned and *plotted on the x-axis*, but it never
enters the price path. `plt.plot(tradingtime, precio_final)` relabels an axis; it
does not subordinate a process. Since the entire content of the Mandelbrot–Fisher–
Calvet model is the composition `X(t) = B_H(θ(t))`, the simulator reproduces none
of the model's characteristic behaviour: no volatility clustering, no fat tails,
no multifractality. It is a Gaussian self-affine process with a stretched axis.

This is a *silent* failure. Every plot the library produces looks plausible.

## 1. Defects that change results

### D1 — the model is never composed  ·  `mmar_simulation.py:88-93`, `:200-206`
As above. `simulacion_fbm = fbm._sample_fractional_brownian_motion(npts-1)` is
indexed by integer step, and `precio_final = self.Price[-1] * np.exp(xt_sim)`.
The fBm must instead be sampled on a fine grid in *trading-time* units and
evaluated at `θ(t_i)`.

### D2 — only half of `f(α)` can ever be recovered  ·  `multifractalcharacteristics.py:12`
The default moment grid is `a=0, b=5` — non-negative `q` only. The left branch of
the singularity spectrum (`α < α₀`) is generated by `q > 0`; the right branch
(`α > α₀`) requires `q < 0`. With `q ≥ 0` the right branch is unreachable *in
principle*, not merely poorly estimated.

Quantified on the binomial measure `m₀ = 0.6`, whose exact support is
`α ∈ [0.7370, 1.3219]`:

| moment grid | reachable α | fraction of the true support |
|---|---|---|
| `q ∈ [0, 3]` (the library's reference script) | `[0.8778, 1.0196]` | **24 %** |
| `q ∈ [−3, 3]` | `[0.8771, 1.1818]` | 52 % |

The library's own `Scripts/pruebaMMAR1.py` runs at `a=0, b=3`. Every published
`f(α)` figure from this code is a left fragment of a spectrum.

For a library whose stated purpose is capturing Hölder coefficients, this is the
most consequential defect.

### D3 — regression standard errors computed in the wrong space  ·  `:92-93, :131-149`
The fit is `log₁₀ S_q = m·log₁₀ Δt + c`, but the leverage terms use the **raw**
scales:

```python
mdeltas   = np.mean(deltas)     # should be mean(log10(deltas))
vardeltas = np.var(deltas)      # should be Σ(log10 Δt − mean)²
```

Observed on the default grid:

```
legacy  SE(slope) denominator = √(n−1)·var(Δt)          = 2.627e+06
correct SE(slope) denominator = √Σ(log Δt − mean)²      = 1.352e+01
ratio                                                    = 1.94e+05
```

The reported confidence intervals are too narrow by roughly five orders of
magnitude. Independently, the formula uses `var` where the algebra requires the
standard deviation, and puts the square root on the sample-size factor instead of
the sum of squares.

### D4 — the confidence interval is negative  ·  `:137, :145`
`t.ppf(alpha / 2, ldeltas - 2)` with `alpha = 0.05` returns the **2.5 %** quantile:

```
t.ppf(0.025, n−2) = −1.9623        (used)
t.ppf(0.975, n−2) = +1.9623        (correct)
```

Every interval half-width carries the wrong sign.

### D5 — the scale grid is linear, so the log–log fit is a coarse-scale fit  ·  `graphs.py:40`
`deltas = np.arange(1, 1000)`: 999 linearly spaced scales. In log space they pile
up at the top.

```
fraction of scales in the upper half-decade of log₁₀ Δt : 96.9 %
```

An unweighted OLS through those points is, to a good approximation, a fit of the
last half-decade. It also violates the sample-size floor: at `Δt = 999` on 7 049
points there are 7 non-overlapping increments, and those seven-sample moments
enter the fit with the same weight as the 7 048-sample moment at `Δt = 1`.
Scales must be geometrically spaced and weighted by window count.

### D6 — τ(0) is not −1, and nothing checks it  ·  observed
For a partition function over `N/Δt` increments, `S₀(Δt) = N/Δt` exactly, so the
slope at `q = 0` is `−1` by construction. Observed on Lockheed:

```
τ̂(0) = −1.017436
```

The 1.7 % discrepancy comes from `X_t[dt::dt] - X_t[:-dt:dt]`, where numpy
silently truncates to the shorter operand when `dt ∤ N`, so the increment count is
not exactly `N/Δt` and varies non-monotonically with `Δt`. τ(0) = −D₀ is a free
self-consistency check on the whole pipeline; the library never performs it.

### D7 — τ is computed from two points  ·  `multifractal_measure_det.py:297-300`
```python
tau = [(func[1] - func[0]) / (deltas[1] - deltas[0]) for func in ...]
```
A two-point finite difference between the two *coarsest* cascade levels
(k = 1 and k = 2, i.e. 2 and 4 cells), used in place of a regression across all
`kmax` levels. Maximal variance, maximal bias, and it discards ten of twelve
available levels.

### D8 — histogram spectrum off by one level  ·  `multifractal_measure_det.py:167, :179`
The coarse Hölder exponents are taken from `measure[-1]`, which is level `kmax`,
but normalised by `log(2**(-(self.kmax - 1)))`. At `kmax = 12` that inflates
`f(α)` by `12/11 = 1.0909` — a 9 % multiplicative bias on the whole curve, in a
routine whose stated purpose is to *measure convergence to the theoretical
spectrum*. `np.log(hist)` on empty bins additionally yields `−inf`.

### D9 — misaligned relative returns for any `Δt > 1`  ·  `graphs.py:138-147`
```python
variacion_prices1 = Price[dt::dt] - Price[:-dt:dt]     # stride dt
media = (Price[:-1] + Price[1:]) / 2                   # stride 1
media = media[:len(variacion_prices1)]                 # first k entries
```
A `Δt`-step difference is divided by the midpoint of the *first* consecutive pair.
Correct for `dt = 1` only; silently wrong for every other value. Confirmed for
`dt ∈ {5, 20}`.

Compounding it: the method computes the relative variation, plots the relative
variation, documents itself as returning the relative variation — and returns the
**absolute** one. `self.variacionprices`, set in the constructor, therefore holds
raw price differences.

### D10 — `UnboundLocalError` on a documented parameter combination  ·  `multifractal_measure_rand.py:174-183`
With `masas1=False, masas2=False` — both documented as booleans the caller may
set — `m00` is never bound:

```
UnboundLocalError: cannot access local variable 'm00' where it is not associated with a value
```

### D11 — dead code shaped like an API  ·  `multifractal_measure_rand.py:232`
`def simulacion(self, grafs=False, results=False)` is defined at module level,
takes `self`, and is bound to no class:

```
hasattr(BinomialMultifractalRand, 'simulacion') → False
```

It duplicates `MMAR.path_simulation` (including D1) and is unreachable.

### D12 — private third-party API  ·  `mmar_simulation.py:88, :201`
`fbm._sample_fractional_brownian_motion(...)` is a private method of `stochastic`.
The module-level name used in `multifractal_measure_rand.py:269`
(`stochastic.FractionalBrownianMotion`) does not exist at all — the class lives in
`stochastic.processes.continuous` — so that path raises `AttributeError` if ever
reached. It is only unreached because of D11.

### D13 — filtering q by a correlation p-value  ·  `:151-164`
```python
cor, pval = stats.pearsonr(np.log10(deltas), np.log10(partition_functions[i]))
qslim = qs[corrtest2 <= alpha]
```
Testing `H₀ : ρ = 0` between `log S_q` and `log Δt` over 999 points has essentially
unit power against any monotone relationship; it rejects for every `q` and
therefore filters nothing. It is not a test of *scaling* — a curved log–log
relation passes it comfortably. The subsequent `if q not in qslim` compares
float64 values by membership.

### D14 — the documented command-line interface does not exist  ·  `Readme.md:37-75`
The README documents six invocations of the form
`python mmar_simulation.py --length 1024 --hurst 0.7 --output ...` and states
that "all scripts include a help option".

```
grep -rn "argparse|__main__|add_argument"  →  no matches anywhere in the package
```

No module is executable, no flag is parsed, and none of the documented options
exists. The entire Usage section is fictional.

## 2. Design defects

### A1 — plotting is a base class of the estimator
`Graphs → MultifractalCharacteristics → MMAR`. Data loading, rendering, estimation
and simulation are one inheritance chain. The estimator cannot be used without
matplotlib, and cannot be tested without a DataFrame with named columns.

### A2 — the constructor runs the analysis
`MultifractalCharacteristics.__init__` computes the partition functions, τ, α,
f(α) and H before returning. You cannot inspect the data before analysing it, and
changing the moment range means rebuilding the object — recomputing everything.

### A3 — boolean flags that change the return type
`multifractal_measure_rand2(..., coef, graf1, cumsum)` returns a 3-tuple, an
`ndarray`, or `None`, depending on three booleans, with a documented precedence
between them. `partition_functions(result=…)`, `compute_tau_and_alpha(results=…)`
and `multifractal_measure_det(coef=…, graf=…)` do the same. This is not typeable
and is why the codebase has no tests.

### A4 — global RNG
Every stochastic routine calls `np.random.*` module-level functions. No seed is
threaded anywhere; no result is reproducible.

### A5 — no tests, no types, no packaging
Zero test files. Zero annotations. `requirements.txt` sits *inside* the package
directory with no version bounds on four of six entries and no packaging metadata,
so the library is not installable — `Scripts/pruebaMMAR1.py` works around this
with a hard-coded `sys.path.append('/Users/omarkhalil/Desktop/…')`.

### A6 — convention never stated
The code fits the slope of `log S_q` against `log Δt` where `S_q` is a **sum**,
which makes that slope `τ(q)` in the measure convention. It then forms
`f = qα − τ`, which is correct *for that convention*. Nothing says so. Anyone
switching the sum to a mean — the more common definition — silently shifts every
exponent by 1 and every `f(α)` by 1. This is the single most common way
multifractal code goes wrong, and there is no guard rail.

## 3. What was right

Worth stating plainly, because most of the mathematics is sound:

- **`H = 1/q*` where `τ(q*) = 0`** is correct MMAR theory, not a heuristic.
  `τ_X(q) = τ_θ(qH)` and `τ_θ(1) = 0` for a conservative cascade, so
  `τ_X(1/H) = τ_θ(1) = 0`. The comment in the source hedges ("a very specific
  interpretation", "use with caution") — the identity is exact.
- **`σ² = 2(λ−1)/ln 2`** is the correct base-2 conservation constraint. From
  `E[2^{−V}] = 2^{−λ + σ² ln2 /2} = 1/2` one gets exactly this.
- **`λ = α₀/H`** is the correct MFC calibration identity, following from
  `α₀^X = H·α₀^θ`.
- **The closed-form binomial `f(α)`** in `f1()` is the correct entropy formula.
- **The cascade multiplication scheme** (flatten level *k*, multiply into level
  *k+1*) is structurally correct, if slow.
- **The bibliography** is genuinely good and has been preserved at
  `docs/BIBLIOGRAPHY_legacy.md`.

The v2 library keeps all of these results and tests each of them against a
closed-form oracle.

## 5. Hypotheses that did not survive testing

Recorded so they are not repeated. Both looked like defects on reading and are
not, at the parameters the library actually uses.

**H1 — "the mass-conservation check rejects valid weights by float equality."**
`multifractal_measure_det.py:70` tests `self.m00 + self.m11 != 1`. Exact float
comparison on a sum *is* fragile in general, but IEEE-754 round-to-nearest happens
to make every natural choice exact:

```
0.1+0.9 == 1.0 → True     0.7+0.3 == 1.0 → True     0.55+0.45 == 1.0 → True
```

No tested weight pair is wrongly rejected. **Downgraded to a latent fragility**
(it would bite on `1/3, 2/3`), not a defect. The real defect at that site is
ordering: the measure is built on line 67 and validated on line 70.

**H2 — "the per-cell Gaussian Ω normalisation produces negative cells."**
`multifractal_measure_rand.py:198-200` multiplies every cell by an independent
`N(2^{λk}, σ)` draw. The mean is astronomically larger than the standard
deviation:

| λ | kmax | E[Ω] | sd | min over 2^k draws | any ≤ 0 |
|---|---|---|---|---|---|
| 1.19 | 13 | 4.54e+04 | 0.740 | 4.538e+04 | no |
| 1.19 | 20 | 1.46e+07 | 0.740 | 1.461e+07 | no |
| 4.00 | 13 | 4.50e+15 | 2.942 | 4.504e+15 | no |

In practice it acts as a near-deterministic rescale that the subsequent
normalisation of the trading time undoes. It is still **conceptually wrong** — the
canonical construction applies a *single* total-mass random variable Ω, not one
per cell, so the intended randomisation of total mass is absent — but it does not
corrupt the output, and it does not produce negative measure. **Downgraded from
critical to a modelling error with no numerical consequence at realistic
parameters.**

## 6. Disposition

The v1 package is preserved verbatim under `legacy/` and remains importable, so
every claim here is reproducible and the thesis results stay auditable. It is not
maintained. `src/mmar/` is a ground-up rebuild; the mapping from old to new is in
`docs/MIGRATION.md`.
